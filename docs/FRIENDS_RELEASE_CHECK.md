# Друзья и уведомления: проверка релиза

## Реализованный путь

1. Клиент отправляет `friend/send` с Firebase ID token. Сервер использует UID из токена, проверяет Premium (включая открытый период до 01.01.2027 по Москве) и блокировки.
2. Одна транзакция записывает заявку, списки обоих пользователей и задание `notificationOutbox`. Повторная отправка ожидающей заявки не создаёт повторное уведомление.
3. Встроенный в API worker создаёт `notificationInboxes/{uid}` и отправляет FCM на зарегистрированные устройства. Разрешение push не нужно для входящих уведомлений внутри приложения. Пользователь может выключить категорию «Друзья»; тихие часы подавляют push, сохраняя историю.
4. Перед доставкой новой заявки worker проверяет, что она ещё ожидает ответа и не заменена повторной заявкой. Уже доставленное уведомление остаётся историей, даже если позднее заявка отменена.
5. Входящие, исходящие и дружба обновляются подписками Firestore. Ошибка подписки не превращается в пустой список; выполняется повторное подключение. Для первого кешированного снимка ждём подтверждения сервера, сохраняя ранее загруженное состояние.
6. Принятие создаёт взаимную дружбу и уведомление отправителю. Повторное принятие уже существующей дружбы безопасно. Встречная отправка принимает ожидающую заявку.
7. В профиле доступны исходящие заявки и отмена. Кнопки действий блокируются на время запроса; ошибки показываются пользователю. Удаление друга требует подтверждения.
8. Переход `#profile-friends` открывает обзор профиля и раскрывает раздел друзей.

## Проверено автоматически

`tests/mutations.test.js`, `tests/notifications.test.js`, `tests/friend-realtime.test.js`: доставка в подменённые Firestore/FCM, адресат и переход, отсутствие дублей, повторные операции, встречные заявки, отмена, блокировки, Premium после тестового периода, ошибки/восстановление подписок, отсутствие обновлений после отписки. Это не подтверждение доставки на реальные устройства.

## Проверка на двух тестовых аккаунтах после установки

- A отправляет заявку B. B видит заявку в профиле и уведомление в колокольчике без перезагрузки. A видит исходящую заявку.
- B открывает уведомление из вкладки «Тариф»: должен открыться обзор и друзья. B принимает: оба видят друга, исходящая заявка A исчезает, A получает уведомление о принятии.
- Удалите дружбу. A отправляет заявку и отменяет: у B заявка исчезает. Снова отправьте и отклоните: у A больше нет ожидающей заявки.
- Для внешнего push на B включите уведомления в приложении, разрешите их браузеру/ОС, включите категорию «Друзья», выключите тихие часы. Выполните встроенную тестовую отправку, затем повторите новую заявку с закрытой вкладкой.
- При ошибке подписок проверьте опубликованные Firestore Rules: `friendRequests` читает отправитель/получатель; `friendships` — участник. Правила в этом релизе не изменялись.
- Проверить API worker: `pm2 logs sportbuddy-api --lines 60 --nostream`. Ищите `[notifications] delivery deferred` и `subscription unavailable`; не публикуйте токены устройств и содержимое `.env`.

Особенности APK нужно проверять отдельно: текущий отправитель использует Web Push. Успешный push в браузере не доказывает работу нативного push в Android-приложении.
