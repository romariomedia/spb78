# Первый блок исправлений аудита 15 октября

База: d4b7129. Production и Firebase из среды разработки не изменялись.

## Исправлено

- Ответ рейтинга возвращает публичную проекцию оцениваемого профиля: без rewardItems, email, заблокированных пользователей, Premium и произвольных новых полей. Ответы мутаций событий/тренировок также проходят проекцию.
- Новый POST /api/activities-list выдаёт авторизованному активному пользователю страницы опубликованных событий и видимых тренировок. Курсор идёт по исходным документам, поэтому полностью скрытая страница не обрывает каталог. Произвольный выбор коллекции запрещён.
- Обычный клиент читает каталоги только через API. Слушатель всей коллекции тренировок заменён видимым опросом раз в 30 секунд. Старый общий кеш v6 и кеш событий v1 удаляются при загрузке новых данных.
- Админка получает все статусы событий отдельным постраничным запросом с OTP-сессией. Черновики не сохраняются в публичный localStorage-кеш. Обновлены обе формы событий: общая и городские спортивные события.
- Firestore rules закрывают прямое чтение events/trainings/venues. Публичные площадки обслуживает существующий API, административные — существующий admin endpoint. В ответе площадок теперь явный список полей.
- Публичный share-preview скрытой официальной тренировки не отдаёт карточку.
- Новая запись на событие требует точной будущей даты. Выход и повтор уже подтверждённой записи разрешены. В форме официального события — календарная дата; legacy-записи без точной даты нужно уточнить вручную. Публикация без даты запрещена; сохранение черновика допускается.
- Изменение события, уведомление и журнал администратора записываются одной Firestore-транзакцией.

## Порядок развёртывания — не переставлять

1. На VPS подготовить и активировать новый commit через ops/prepare-release.sh и ops/activate-release.sh. Проверить health, авторизацию, каталоги, ленту и админку. Новые API должны быть доступны ДО установки нового APK.
2. Собрать новый подписанный APK из этого commit с увеличенным versionCode. Установить поверх прежнего тем же ключом.
3. Проверить на новом APK: опубликованные события и тренировки видны; скрытые отсутствуют; карта площадок работает; админ видит черновики; регистрация на будущее событие и выход работают; уточнить даты старых событий. Проверить сайта и телефона двумя аккаунтами.
4. Только после этих проверок опубликовать firestore.rules из ТОГО ЖЕ commit в Firebase (правильный проект sportbuddy-spb).
5. Подтвердить отказ прямого чтения events/trainings/venues/feed с пользовательским токеном и успешное чтение через новые API. Проверить отсутствие устаревшего кеша после обновления.

После шага 4 старые APK, читающие каталоги напрямую, не смогут обновлять их. На этапе текущей беты обновить все тестовые установки. Это преднамеренная миграция, а не бесшовная совместимость со старыми APK. Автоматическая проверка минимальной версии пока не внедрена. Кешированные ранее данные нельзя отозвать с чужого устройства задним числом.

Откат: до публикации rules возможен штатный откат приложения. После публикации rules нельзя откатываться на версию с прямыми чтениями без потери каталогов; предпочтителен исправляющий релиз с текущим API, а не открытие коллекций.

## Проверки и пределы

Регрессионные тесты: приватность ответа рейтинга, скрытые/legacy записи, скрытые страницы и курсоры, auth и выбор коллекции, истёкшая/отсутствующая дата, повтор записи/выход, московское время, атомарность события и аудита, новые загрузчики и опрос. Production Firebase rules не опубликованы и в этой среде не проверены через эмулятор. Нужна приёмка на реальных тестовых аккаунтах.

## Остальные пункты аудита остаются отдельными задачами

Нативные фоновые push, механизм обновления APK, полное восстановление блокировки Auth/Firestore после сбоя, управление промокампаниями/остатками BOX, подпись медиазагрузок, расширенная пагинация/нагрузка, резервирование и проверка восстановления данных. Этот релиз не объявляет их решёнными.
