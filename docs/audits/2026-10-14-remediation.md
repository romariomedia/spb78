# Исправления после аудита 14 октября 2026

База: c52cfda. Изменения подготовлены для main; production обновляется отдельно владельцем VPS.

## Сделано

- Лента читается через авторизованный feed-list, со страницами по 100 документов и явным списком публичных полей. Скрытые посты исключаются на сервере. Ответы лайков/комментариев также очищены от служебных данных. Клиент больше не читает и не слушает коллекцию feed напрямую; обновляет её через API. Старый кеш v5 удаляется.
- firestore.rules запрещает прямое чтение feed. Защита полностью вступит в силу только после публикации этих правил в Firebase.
- Ошибки загрузки жалоб, аналитики и дашборда не подменяются пустыми списками/нулями.
- Настройки сохраняются транзакционно с аудитом. Модерация, отзыв админской сессии и аудит записываются пакетом; изменения Premium/верификации — транзакцией с причиной. Это не распределённая транзакция между Firebase Auth и Firestore: блокировка аккаунта по-прежнему требует отдельного дальнейшего усиления восстановления после сбоя.
- Доступность знакомств, активного отдыха, Stories, ID, BOX применяется интерфейсом и сервером VPS; push-переключатель останавливает внешнюю отправку, сохраняя внутреннюю историю. Техническое обслуживание блокирует обычные API, сохраняя админский доступ и платёжный webhook. Это не глобальный запрет всех прямых чтений Firestore.
- Ранее неработавшие значения не активируются автоматически: версия настроек становится действующей после сохранения. Даты беты/BOX закреплены, управление минимальной версией APK обозначено как неподключённое.
- В админке страницы по 100 аккаунтов, точный поиск UID/email, продолжение текстового поиска по следующим страницам. Журнал действий получил следующие страницы и детали изменений.
- APK читает внутреннюю историю уведомлений через native HTTP раз в 15 секунд, пока приложение видно. Запросы не перекрываются, ответы прежнего аккаунта игнорируются. Это НЕ фоновые push закрытого приложения.

## Проверка

274 автоматических теста: успешны. TypeScript, production build и Capacitor sync проверены. Тесты используют подмену внешних сервисов; реальный телефон и развёрнутые правила Firebase этим не подтверждаются. Lockfile не изменялся относительно аудита, где было 0 известных уязвимостей.

## Порядок развёртывания

1. Подготовить и активировать этот commit стандартными ops/prepare-release.sh и ops/activate-release.sh на VPS.
2. Проверить сайт: лента, жалобы, поиск аккаунтов, сохранение/обратное включение флага. Не включать техническое обслуживание без необходимости.
3. Собрать и установить APK из того же commit с новым versionCode. Проверить ленту и уведомления.
4. Опубликовать firestore.rules из этого commit через Firebase CLI или консоль. Старые APK с прямым чтением feed после этого не смогут обновлять ленту: их необходимо заменить. До публикации правил прежний прямой доступ остаётся открытым. Не оставлять этот шаг незавершённым.
5. Перепроверить: авторизованное прямое чтение feed запрещено, feed-list возвращает видимые посты, скрытие убирает пост после обновления, админка продолжает видеть его.

После ужесточения правил откат на старый APK/сайт не вернёт чтение ленты. Предпочтителен исправляющий релиз с новым API; не открывать коллекцию ради отката.
