# Аудит админки SportBuddy78 — 20 октября 2026

База проверки: `e33e59725c98501a47fd82eea4c50c597600c24e` (main).
Проверка исходников интерфейса, сервисов и API; локальные автоматические тесты с изолированной базой; production-сборка. Реальные записи, пользователи и рассылки на VPS не изменялись.

## Исправленные дефекты

1. **Официальные тренировки, высокий приоритет.** Чтение участников выполнялось до записи: одновременная запись пользователя могла потеряться при редактировании/завершении/отмене. Все операции теперь читают актуальную тренировку и чат внутри одной транзакции. Список участников сохраняется. Нельзя уменьшить вместимость ниже числа участников, изменить закрытую тренировку или обойти завершение через поле статуса. Скрытие архивирует чат, повторная публикация открывает его. Удаление с участниками и удаление завершённых запрещены.
2. **Сохранение и журнал, высокий приоритет.** Площадки, отдых, партнёры, объявления, официальные тренировки, push, подтверждения Спортивного ID и результаты соревнований записывались отдельно от журнала. При отказе журнала API сообщал ошибку после фактически выполненного изменения. Теперь изменения и журнал фиксируются атомарно. Импорт каталогов не перезаписывает существующие карточки.
3. **Спортивный ID.** Проверка актуального достижения и статуса заявки перенесена в транзакцию. Подтверждение, отклонение и отзыв не могут одновременно обработать одну заявку разными статусами. Ошибка загрузки результатов соревнования больше не маскируется пустым списком.
4. **Городская афиша.** Публикация медиалиги без продажи билетов была заблокирована общей проверкой. Для медиалиги оставлен обязательный официальный источник; для обычных матчей сохранены подтверждённые билеты. Ошибки загрузки и удаления теперь показываются в редакторе.
5. **Редактор мероприятий.** Блокировка повторного нажатия сохранения и сохранения во время загрузки медиа; полный сброс формы при создании после редактирования; показ причины отказа API вместо общего сообщения.
6. **Объявления.** Сохранение заблокировано до завершения загрузки изображения.
7. **Админ-сессии.** Неправильные типы/пути идентификаторов отклоняются до обращения к Firestore. Некорректный срок действия больше не считается действующей сессией на клиенте/сервере.

## Оставшиеся ограничения

- **Удаление аккаунта:** операция распределена между Firestore BulkWriter и Firebase Auth и не является общей транзакцией. При сбое возможна частичная очистка. Сейчас есть dry-run, подтверждение и блокирующие условия, но перед массовой очисткой нужен отдельный возобновляемый процесс удаления с фиксацией прогресса и ошибок каждой записи. В этом обновлении механизм удаления не перепроектирован.
- Часть админских списков ограничена последними 50–200 записями без пагинации (модерация, партнёры, массаж, верификация). Это не весь каталог при росте выше лимита. Пользователи, события и журнал имеют отдельную постраничную загрузку.
- Существующие операции создания карточек с генерируемым ID не дают полной защиты от повтора после обрыва связи уже после успешного ответа сервера. Кнопки блокируются во время запроса, но для гарантии при сетевых повторах нужен сохраняемый сервером ключ идемпотентности.
- Счётчики обзора включают документы коллекций (в том числе закрытые/старые объекты), а не только опубликованные предложения. Это операционный обзор, не точная воронка продаж.
- Полная работоспособность в production требует ручного прохода после выкладки; результаты тестов с изолированной базой не подтверждают доставку почты/FCM, права медиахранилища или особенности Android WebView.

## Проверка после выкладки

1. Войти через пароль + OTP, открыть обзор, пользователей и журнал. После выхода убедиться, что админка снова требует вход.
2. Создать один явно тестовый черновик площадки/отдыха/массажа/партнёра/объявления; сохранить, повторно открыть, изменить, скрыть. Проверить соответствующий публичный раздел и журнал. Удалить только эти тестовые записи.
3. Создать официальную тренировку: площадка и точка на карте; с отдельного тестового аккаунта записаться. Изменить название, проверить сохранность участника, скрыть и повторно опубликовать, затем отменить.
4. Создать черновик афиши и проверить сохранение источников/даты. Для медиалиги проверить публикацию без ссылки покупки.
5. На тестовом аккаунте проверить подтверждение/отзыв Спортивного ID и результат завершённого тестового соревнования.
6. Проверить загрузку фото и видео; дождаться загрузки перед сохранением.
7. Для проверки доставки push использовать только отдельный тестовый аккаунт. Массовую рассылку аудитории аудит не отправлял.

Новый APK нужен для изменений интерфейса. Серверные исправления начинают действовать после выкладки VPS и применяются также к существующим версиям APK.
