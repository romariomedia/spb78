# Уведомления SportBuddy: web, первый релиз

Публичный VAPID-ключ проекта sportbuddy-spb подключён. Секреты в клиент не добавлены. Отправка выполняется Firebase Admin SDK на существующем VPS; Cloud Functions/Blaze не используются. Firebase Console и доставку на реальное устройство нужно проверить после установки: локальные тесты не подтверждают права серверного аккаунта в FCM.

## Что реализовано

- Серверная история: чаты, заявки/принятие дружбы, подходящие новые тренировки, запись участника организатору, публикация и изменения официальных событий для участников.
- Данные события и запись очереди создаются одной транзакцией Firestore. Отправка не задерживает ответ чата.
- История ограничена 100 записями; UI показывает последние 30 дней. Старые записи физически удаляются при следующем пополнении истории, отдельного фонового удаления пока нет.
- Настройки категорий, радиус 5–100 км, тихие часы 23–08 по Москве. Категории отключают новые записи данной категории и push. Тихие часы подавляют push, история остаётся. Выключение push на устройстве не выключает историю.
- Подбор тренировок: интересы и координаты из профиля, пол участников, дата, вместимость. Официальные анонсы получают пользователи с включённой категорией событий.
- Текст переписки не отправляется через FCM. Переход из push открывает нужный чат/тренировку/событие; снятое событие ведёт к списку. Заявки ведут к раскрытому разделу друзей.
- Проверочная отправка только себе, не чаще раза в минуту. Она не зависит от категорий и тихих часов.
- Прочтение синхронизируется между устройствами. HTTPS POST-stream с проверенным ID token; заголовок X-Accel-Buffering: no и heartbeat 20 секунд. Новые клиентские права Firestore не требуются: коллекции закрыты правилом default deny в текущем firestore.rules.

## Очередь и расходы

Работник очереди запускается внутри одного PM2-процесса sportbuddy-api, чтобы обновление и откат включали его автоматически. Источник истины — notificationOutbox в Firestore, перезапуск не теряет очередь. Snapshot-подписка заменяет частый опрос базы; история открытой сессии тоже получает изменения потоком. Стандартные индексы Firestore, без составных индексов.

Повторные попытки имеют задержку, максимум 8; затем задание получает status=failed. У задания срок актуальности 24 часа. Просроченное задание удаляется без доставки. Остальные задания продолжают обрабатываться. Неудачная отправка одному устройству может повторить отправку другому: доставка at-least-once, одинаковый tag заменяет web-уведомление, eventId предотвращает дубль в сохранённой истории в пределах её окна. Абсолютная exactly-once доставка push не гарантируется.

Рассылка обходит профили страницами по 50. Firestore чтения/записи учитываются в квотах Spark; FCM бесплатно не означает безлимитную базу. Следить за Usage Firestore и логами [notifications]. Не масштабировать PM2 на несколько экземпляров без дополнительной проверки длительности lease и работы потоков.

## Проверка после установки

1. В Firebase Settings → Cloud Messaging убедиться, что Firebase Cloud Messaging API (V1) включён; если регистрация браузера сообщает об отключённом API — включить также FCM Registration API именно для sportbuddy-spb. Не включать Legacy API.
2. Открыть сайт, войти и нажать колокольчик → «Включить уведомления на устройстве», разрешить браузеру уведомления.
3. Нажать «Отправить проверочное уведомление». Дождаться записи в истории и системного уведомления «SportBuddy на связи». Кнопка подключает только это устройство.
4. Проверить два тестовых аккаунта: заявка, принятие, сообщение, прочтение на другом устройстве. Проверить переход в чат друзей, а не только мэтчей.
5. Закрыть вкладку и повторить входящее сообщение с другого аккаунта. Проверить настройки ОС; доставка зависит от браузера, сети и разрешений. На iPhone сайт должен быть добавлен на домашний экран.
6. Выйти из аккаунта и убедиться, что push прежнего аккаунта больше не отображаются. Service worker сверяет получателя с локальной активной учётной записью; выход очищает её, удаляет локальную регистрацию и отвязывает устройство на сервере.

Если история приходит, а системного уведомления нет: проверить разрешение браузера/ОС, регистрацию устройства и `pm2 logs sportbuddy-api --lines 40 --nostream`. Логирует только код ошибки, токены не печатает. permission-denied / mismatched-credential требуют проверки прав сервисного аккаунта и совпадения Firebase-проекта. Исправление конфигурации и повторное нажатие теста безопаснее ручного переотправления всей очереди.

## Границы этого релиза

Web-push для сайта/PWA. Нативный Android push не подключён: нужен отдельный Firebase Android app, google-services.json, Capacitor-плагин и новая APK. В Android остаётся внутренняя история. Серверные напоминания по расписанию и отдельные наградные push — следующий этап; существующие локальные напоминания и сообщения о наградах сохранены. Старые чаты/заявки не рассылаются задним числом.
