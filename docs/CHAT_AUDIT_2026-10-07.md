# Аудит чатов SportBuddy78 — 07.10.2026

## Область проверки

Проверены пользовательские чаты и связанные контуры:

- открытие чата после взаимного мэтча;
- открытие чата между друзьями;
- серверная отправка сообщений;
- Firestore realtime;
- отметка прочтения;
- счётчик непрочитанных;
- push/внутренняя история уведомлений;
- deep-link из уведомления в нужный чат;
- offline-cache;
- жалобы и Moderation Center;
- safety-warning для небезопасных предложений;
- Firestore Security Rules;
- поведение при блокировках/ограничении аккаунта;
- UX списка диалогов и открытого разговора.

## Найдено и исправлено

### 1. Критично: бесконечный массив сообщений внутри одного Firestore document

До аудита весь диалог хранился в `chats/{chatId}.messages[]`.
Каждое сообщение переписывало весь документ. При активном диалоге это неизбежно приближало документ к лимиту Firestore и повышало конфликтность транзакций.

Исправление Chat Storage v2:

- полная новая история: `chats/{chatId}/messages/{messageId}`;
- основной chat document содержит только метаданные и последние 60 сообщений как bounded cache;
- при первой новой отправке старые последние сообщения лениво копируются в v2 subcollection;
- открытый чат подписывается на последние 200 сообщений;
- metadata document больше не растёт бесконечно.

### 2. Высокий риск приватности: общий localStorage-cache между аккаунтами устройства

Ранее использовался один ключ `sportbuddy_chats_spb_v1`.
При последовательном входе разных людей на одном устройстве технически сохранялся общий локальный набор диалогов.

Исправлено:

- cache v2 изолирован по Firebase UID;
- при logout cache текущего пользователя удаляется;
- другой пользователь устройства не получает локальную историю предыдущего аккаунта.

### 3. Сервер не запрещал сообщение заблокированному/ограниченному собеседнику

Friend flow уже учитывал `blockedUserIds`, chat-send — нет.

Исправлено:

- сервер проверяет блокировку в обе стороны;
- нельзя писать временно ограниченному пользователю;
- взаимный match/friendship повторно проверяется сервером на каждую отправку;
- chatId обязан соответствовать детерминированной паре UID.

### 4. Непрочитанные считались только в открытой категории

Bottom navigation могла показывать, например, непрочитанные «Мэтчи», но не учитывать непрочитанные сообщения друзей, пока пользователь не переключил категорию.

Исправлено:

- один Firestore listener получает все чаты пользователя;
- selected category используется только для UI;
- общий badge считает непрочитанные одновременно по «Мэтчам» и «Друзьям»;
- сервер хранит scalable `unreadCount` metadata.

### 5. Статус online был связан с activeLooking

Зелёная точка означала «активно ищет», а визуально выглядела как online presence.

Исправлено:

- online indicator теперь основан на `lastSeenAt` за последние 5 минут;
- `activeLooking` больше не выдаётся за сетевой статус.

### 6. Жалоба была слишком далеко от конкретного диалога

Раньше пользователь открывал общую форму и снова выбирал собеседника.

Исправлено:

- в шапке открытого чата есть «Пожаловаться»;
- ComplaintModal сразу выбирает текущего собеседника;
- сервер по-прежнему сам проверяет реальное участие в chatId;
- в Moderation Center попадает server-side excerpt последних сообщений.

### 7. Moderation excerpt подготовлен для Chat Storage v2

`api/report.js` теперь берёт последние сообщения из v2 subcollection, а для legacy-диалогов сохраняет fallback на bounded chat cache.

### 8. Защита от технического message flood

Добавлен мягкий server-side rate limit между сообщениями одного отправителя.
Он не мешает обычной переписке, но ограничивает автоматические сверхбыстрые POST-запросы.

## UX-доработки

- поиск по имени, виду спорта и последнему сообщению;
- автопрокрутка открытого диалога к новым сообщениям;
- отдельное состояние отправки, защита от двойного клика;
- max length 2000 символов синхронизирован с сервером;
- счётчик символов около лимита;
- read receipt «доставлено / прочитано» для последнего исходящего;
- offline-warning для history listener;
- правильный badge «МЭТЧ» / «ДРУГ» в шапке;
- прямой вход в жалобу из открытого разговора;
- удалён неиспользуемый demo auto-reply, чтобы production никогда не создавал искусственные сообщения.

## Что уже было сделано правильно

- сообщение создаётся только через server-authoritative mutation API;
- прямые записи клиента в chats запрещены Firestore Rules;
- читать чат может только его участник;
- send повторно проверяет mutual match/friendship;
- текст сообщения не отправляется в FCM push;
- push category учитывает пользовательскую настройку Messages;
- quiet hours не удаляют историю уведомления;
- readAt синхронизируется между устройствами;
- complaint backend не доверяет переданному target без проверки chat participants;
- React рендерит текст сообщения как текст, без raw HTML;
- chat deep-link содержит только chatId, а доступ повторно ограничен Firestore rules.

## Следующий уровень, не являющийся блокером текущего релиза

Эти возможности намеренно не добавлены в данный production-safe аудит:

1. отправка фото/видео в личных сообщениях;
2. reply-to-message;
3. редактирование/удаление сообщения;
4. typing indicator;
5. групповые чаты тренировок;
6. pagination старше последних 200 сообщений;
7. пользовательский экран управления заблокированными аккаунтами.

Их лучше делать отдельной вертикалью, потому что каждая меняет модель данных, moderation/storage cost или privacy contract.

## Production checklist после deploy

1. Аккаунт A и B создают mutual match.
2. A отправляет сообщение B.
3. B получает внутреннее уведомление/push без текста сообщения.
4. Переход по уведомлению открывает правильный chat.
5. Badge непрочитанных виден независимо от вкладки «Мэтчи/Друзья».
6. B открывает чат — у A появляется «прочитано».
7. Проверить чат друга отдельно от мэтча.
8. Нажать «Пожаловаться» прямо в чате — собеседник уже выбран.
9. В Moderation Center проверить excerpt.
10. Выйти A и войти другим тестовым аккаунтом на том же устройстве — локальная история A не должна отображаться.
11. Проверить Firestore: новый message существует в `chats/{chatId}/messages`, а основной chat document остаётся bounded.
