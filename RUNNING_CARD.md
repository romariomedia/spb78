# Карточка результата

Редактор использует существующие результаты пробежек, не меняя правила рейтинга.
Три режима: пейзаж маршрута (одна из трёх существующих ИИ-иллюстраций), своё фото,
прозрачный фон. Для свободной пробежки без каталожного маршрута пейзаж недоступен.

Фото JPG/PNG/WebP до 20 МБ декодируется локально, уменьшается до 2400 px по длинной
стороне; исходные метаданные не переносятся. Фото не загружается на сервер и не
сохраняется после закрытия редактора. Пользователь управляет масштабом, положением
и затемнением. Читаемость нижнего блока поддерживает постоянный градиент.

Экспорт — PNG 1080×1350, тот же файл, который показан в предпросмотре. В прозрачном
режиме фон и градиент не рисуются, шахматная подложка остаётся только в интерфейсе.
Доступны светлый и тёмный текст. Пока новый вариант не отрисован, экспорт выключен.

Браузер использует готовый File для Web Share, сохраняя пользовательский жест;
при отсутствии поддержки отправки файлов предлагается скачивание. Новый Android
APK использует ACTION_CREATE_DOCUMENT для сохранения и ACTION_SEND для отправки.
Старый APK без saveCard продолжает работать через меню отправки с пояснением.
Отмена системного диалога не отображается как успешное сохранение.

## Проверки

- `npm run build` и `npm test`.
- GitHub workflow Running Android check: APK, JVM tests, компиляция instrumentation.
- Browser job: реальный Chromium, выбор пейзажа, локальное фото/ошибка декодирования,
  изменение кадра, удаление, отмена share, несохранённые результаты, отсутствие GPS,
  смена маршрута, ширины 320/390/768, отсутствие POST, размеры и alpha-канал PNG.
  Артефакт `running-card-previews` содержит изображения и `checks.json`.
- Ручной предпросмотр: `npm run dev`, затем
  `/scripts/running/result-card-preview.html`. Это тестовая страница, не входящая
  в production build. Для browser script установить Playwright отдельно и задать
  `PLAYWRIGHT_PACKAGE` путём к его пакету.

До выпуска проверить на физическом Android: выбор фото из галереи, отмену выбора,
сохранение в локальную папку, отмену сохранения, отправку PNG в мессенджер, а также
сохранение прозрачности в самом файле (мессенджер может перекодировать изображение).
Подписанный APK и публикация production/RuStore выполняются отдельным этапом.
